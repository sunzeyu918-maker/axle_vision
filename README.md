# 智轴通 SmartAxle · 车辆轮轴智能识别系统

**简体中文** | [English](README_EN.md)

摄像机（或本地视频）采集画面 → 运动检测触发 → 车轮检测 + 多目标跟踪 → 过轴计数、单双胎与车型判定 →
保存整车侧面展开图、写识别记录，并按协议把结果实时发给上位机（串口 / TCP / HTTP）。

## 功能特性

| 特性 | 说明 |
| --- | --- |
| 离线本地推理 | 内置 OpenVINO（CPU/GPU），缺库时自动回退 onnxruntime，模型直接吃 `models/*.onnx`，无需外网 |
| 便携运行 | 全部数据（配置 / 日志 / 结果图）落在程序目录，整体拷贝即可迁移；另提供 Windows 打包脚本，可产出免安装绿色版 |
| 识别要素 | 轴数、单双胎序列（车型代码）、轴距、整车拼接展开图 |
| 对接能力 | 5 种外发协议：串口协议1 / 串口协议2 / 网口TCP协议1 / HTTP 上报 / TCP 服务端 |
| 无人值守 | 托盘常驻、开机自启、单实例、断流自动重连、无预览模式（省 CPU） |

## 1. 快速开始

### 1.1 环境要求

* Windows 10 / 11（界面、托盘、串口与自启均按 Windows 平台验证）。
* Python 3.8+（本工程在 3.12 验证）。
* 视频源三选一：海康网络摄像机（有 HCNetSDK 时走 SDK）/ 通用 RTSP 摄像机 / 本地视频文件。

### 1.2 安装与运行

```powershell
git clone <本仓库地址>
cd axle_vision

# 方式一：一键脚本（双击即可，自动建/复用 .venv 并装齐依赖）
安装依赖.bat

# 方式二：手动安装
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt

# 启动程序
.\.venv\Scripts\python main.py
```

首次运行会自动释放 `models/`、`Icon/`，并按内置默认生成 `configs/config.ini`（已有配置不会被覆盖）。

### 1.3 首次配置（三步）

| 步骤 | 做什么 | 在哪 |
| --- | --- | --- |
| 1 | 填相机 **用户名 / 密码 / IP**，Mode 选 `Camera` | 左上"网络摄像头信息" |
| 2 | 框出检测区（车道所在的多边形），必要时调 **置信度** | 主画面 + 底部参数区 |
| 3 | 选 **通讯协议**，填 **转发地址 IP:端口** → 点"测试连接" | 底部参数区 |

然后点 **打开摄像头** 开始检测；点 **停止检测** 结束本次检测（可重新开始）。
手头没有摄像机时，Mode 选 `Local Video` → "选择文件"，即可用本地视频跑完整识别流程。

### 1.4 数据目录（重要）

程序把配置、日志、结果图都写在**程序所在目录**，整个目录可随程序一起拷贝迁移：

| 路径 | 内容 |
| --- | --- |
| `configs/config.ini` | 全部配置（含相机账号密码，**不要外传 / 提交到仓库**，已默认被 `.gitignore` 排除） |
| `log/log.txt` | 程序运行日志（启动自检、界面操作、相机状态） |
| `log/worker.log` | 识别线程日志（检测、计数、拼接、**每次转发去向**） |
| `log/record.txt` | 识别记录（时间、轴数、轮型、车型、轴距） |
| `img/YYYYmmddHHMMSS.jpg` | 每辆车的整车拼接展开图 |

### 2.1 采集源与方向

| 控件 | 含义 |
| --- | --- |
| Mode `Camera` / `Local Video` | 两个入口**互斥**：选 Camera 只有"打开摄像头"可用，选 Local Video 只有"选择文件"可用 |
| 打开摄像头 | 按 IP + 账号密码取流；存在海康 HCNetSDK 时走 SDK，否则自动改用 RTSP |
| 选择文件 | 跑本地视频，用于离线复核（检测流程与相机完全一致） |
| 检测方向 | 左到右 / 右到左 / 无方向。左右计数会自适应该方向，并决定拼接切片的镜像方向 |

### 2.2 检测框（ROI）：矩形 → 多边形

* 交互：**拖动顶点**变形、框内拖动**整体平移**、**双击边**插入顶点、**右键顶点**删除（最少保留 3 点）。
* 语义分工（重要）：
  * **多边形只约束运动检测** —— 框外像素在运动判定前被置黑（"哪些区域的动静算数"）；
  * **AI 识别区取多边形的外接矩形**（模型输入必须是矩形），所以"左上角/右下角"输入框照常显示外接矩形坐标；
  * 过轴计数中线 = 外接矩形的水平中心。
* 顶点保存在 `detection/roi_points`（`x1,y1;x2,y2;...`）；空 / 非法 / 少于 3 点时**自动回退旧矩形行为**，旧配置零迁移。

### 2.3 底部参数区

| 控件 | 含义与要点 |
| --- | --- |
| COM + **检测** | 测试所选串口能否打开，结果**弹窗提示** |
| 最大 / 最小 / 默认轴数 | 结果过滤与缺省判定 |
| 开机启动 / 自动运行 | 开机自启写注册表；自动运行＝程序启动即开始检测 |
| 通讯协议 | 串口协议1 / 串口协议2 / 网口TCP协议1 / TCP 客户端模式 / TCP 服务端模式 |
| 检测灵敏度 | 运动检测阈值（1000~5000，默认 4000，越小越敏感） |
| **置信度** | 车轮检出阈值（0.3~0.8，**现场建议 0.50~0.55**）。调低减少暗色/远处车轮漏检（避免漏轴），调太低会误检导致多算轴。**检测运行中改动即时生效** |
| 转发地址 + 测试连接 | 上位机 `IP:端口`；**运行中修改立即生效**，无需重启程序 |

### 2.4 预览画面 / 停止自动恢复

* **取消勾选"预览画面"** ＝ 无预览模式：不再渲染实时画面，主画面显示"正在无预览模式检测中"状态图，
  CPU 占用显著下降，适合无人值守。识别、计数、转发、落盘全部照常。
* **"停止自动恢复"**：勾选后，采集卡顿或画面停滞超过阈值时程序自动重连相机
  （阈值 `camera/offtime`，默认 50000 次心跳）。

### 2.5 退出

* 窗口右上角关闭 = **隐藏到托盘**，程序继续运行。
* 真正退出：托盘图标右键 → **退出(Exit)**。
* 运行期间任务管理器里会有 **2 个同名进程**（主进程 + AI 检测子进程），退出后两者都应消失。

## 3. 识别流程

```
采集线程(摄像机/视频) --帧--> 队列 --> 检测子进程(推理+跟踪+计数+拼接)
                                            |-- 结果队列 --> 主界面表格 / 结果图
                                            |-- 协议外发 --> 串口 / TCP / HTTP
                                            '-- 落盘 --> log/record.txt、img/*.jpg
```

| 环节 | 实现说明 |
| --- | --- |
| 视频接入 | 海康 SDK（可选，需 HCNetSDK 目录）/ RTSP / 本地视频文件 |
| 车辆到达 | 帧差运动检测 + 灵敏度阈值 + ROI 多边形蒙版；连续运动帧确认后进入识别 |
| 车轮检测 | **OpenVINO** 推理（缺库回退 onnxruntime），ONNX 模型在 `models/`；ROI 裁剪 → 缩放 320 → NMS → 置信度过滤 |
| 跟踪 | Sort（卡尔曼预测 + IOU 匹配；存活轨迹即输出，不做 min_hits 过滤） |
| 过轴计数 | 以 ROI 竖向中线为触发线，车轮中心跨线计数，向左 / 向右分别累计 |
| 单双胎 | 同轴左右两个车轮配对判断，得出单/双序列（如"单双双双双"） |
| 车型判定 | 单双序列 + 轴距经验值 → 车型代码 |
| 整车拼接 | 以**整车帧间位移**（所有可见车轮位移的中位数 + 最近 7 帧滚动中位数平滑）为切片宽度，逐帧横向拼成整车侧面展开图 |
| 结果落盘 | `log/record.txt` + `img/YYYYmmddHHMMSS.jpg` |
| 结果外发 | 5 种协议（见第 5 节） |

> **成像与轴数同源**：车轮没被检出就既不会被计数、也不会进展开图。
> 排查"展开图少一根轴"和"轴数少一根"要当同一个问题查，先看置信度阈值与 ROI。

| 12 | 单双 | 125 | 单双双双 |
| 112 | 单单双 | 152 | 单双双双 |

## 5. 对外协议（`service/protocols.py`）

| 协议 | 通道 | 报文 |
| --- | --- | --- |
| 0 串口协议1 | 串口 | `A5 5A <轴数HEX> 5A A5` |
| 1 串口协议2 | 串口 | `65 6B 0<相机号> 0<方向> 0<轴数> [01\|02]... 0A 0D` |
| 2 网口TCP协议1 | TCP 客户端 | 同串口协议2 报文的十六进制串 |
| 3 HTTP 上报 | HTTP 客户端 | `POST /identify/axles`，JSON：`camera / camers_ip / kkinds / report_type / wheels` |
| 4 TCP 服务端 | 监听端口 | 上位机连上后推送 `A5 5A <轴数> 5A A5` |

* **轴数字段一律以判定轴数为准**（不是轮型串位数）。轮型串少一位时（手持视频抖动等），报文仍按判定轴数上报，
  同时 `log/worker.log` 会写一条 WARNING 提示该次轮型可能缺位。
* 帧长 ＝ 6 + 轮型段字节数；`0A 0D` 为结束符。HTTP 模式 3 秒超时、不重试。
* 逐字节说明、示例报文、对接步骤、联调脚本与验收用例见 `docs/第三方系统对接文档.md`。
* 排查：`log/worker.log` 每次发送都有一行 `转发目标 host:port`，可直接核对结果推去了哪里。

## 7. 打包构建（可选）

交付 / 分发时可用脚本打免安装绿色版与安装包：

| 脚本（双击即可） | 作用 |
| --- | --- |
| `安装依赖.bat` | 建 / 复用 `.venv`，装齐运行依赖 + `pyinstaller`（版本按已验证环境锁定：PySide6 绑定，不含 PyQt5 / scipy） |
| `一键打包.bat` | 清旧产物 → PyInstaller 打绿色版文件夹 → 用 Inno Setup 编译安装包 exe（约 3~6 分钟） |

也可手动分两步执行（中文文件名经管道调用会报"路径不存在"）：

```powershell
.\.venv\Scripts\python.exe -m PyInstaller build.spec --noconfirm --clean
& "$env:LOCALAPPDATA\Programs\Inno Setup 6\ISCC.exe" installer\SmartAxle.iss
```

* 未装 Inno Setup 时打包脚本会自动跳过安装包、只输出绿色版文件夹。
* **为什么不用单文件（onefile）**：单文件版每次启动把约 360 MB 解压到 `%TEMP%\_MEIxxxxxx`、退出时再删，
  只要有文件被占用（检测子进程、OpenVINO DLL、杀毒扫描）就会弹
  `Failed to remove temporary directory` 并留下残留。
  文件夹版不自解压、不写临时目录，实测启动到界面 **1.7 秒**。
* 安装包**不包含** `configs/config.ini`（相机账号密码、ROI 标定、协议地址等现场参数）：
  首次运行由程序按内置默认生成，升级安装不会覆盖已调好的配置。
* 打包注意：**删 `dist` 前必须先退出正在运行的程序**（文件被占用会导致删除静默失败、PyInstaller 随后失败）。

## 8. 推理后端（OpenVINO / onnxruntime）

`[detection] backend`：`auto`（默认，优先 OpenVINO，失败自动回退）/ `openvino`（强制，仍兜底 onnxruntime）/
`onnxruntime`（强制）。
`[detection] ov_device`：`CPU`（默认）/ `GPU` / `AUTO`，设备不可用时自动回落 CPU。

本机实测（`models/model.onnx`，320×320 输入，200~300 次取中位数）：

| 线程数 | OpenVINO | onnxruntime |
| --- | --- | --- |
| 1 | 6.15 ms | 6.17 ms |
| 2 | 3.71 ms | 3.53 ms |
| 4 | **2.13 ms** | 3.01 ms |

* 两后端输出数值一致（最大绝对误差约 1e-6），端到端检出的车轮框数量与位置完全相同。
  复现：`python tests/compare_backends.py --threads 4`。
* 同一台机器上 `ov_device=GPU` 单帧慢于 CPU（320×320 小模型上显存搬运开销盖过算力优势），
  因此默认保持 `CPU`；换更大输入（如 `models/tyre_640.onnx`）或整机 CPU 很弱时再试 `GPU` / `AUTO`。

## 10. 故障排查

| 现象 | 先看什么 | 处理 |
| --- | --- | --- |
| 结果推不到对端 | `log/worker.log` 的 `转发目标 host:port` 与报错 | 协议类型是否与对端一致；点"测试连接"；改完地址**不需要重启**（已支持热更新） |
| 轴数比实际少一根 | `log/worker.log` + 展开图 | 多为**某根轴的车轮被漏检**：置信度 0.8 → 调至 0.50~0.55；确认 ROI 已覆盖车道；实测 0.45 以下会多算轴 |
| 展开图重影 / 有缺口 | `out/vp_frames.csv`（`video_probe`） | 拼接宽度取自整车帧间位移，车辆变道 / 相机抖动时可能失真；固定相机安装可缓解 |
| 车型代码与轮型串不一致 | 轮型串位数 | 手持 / 抖动大的视频会让轴距估计掉一位字符；**轴数正确**，报文轴数也正确；固定相机素材待复测 |
| 打开摄像头失败 | `log/log.txt` + 界面弹窗 | 弹窗含 IP 与异常原因；确认账号密码、IP 可达、端口开放；无 SDK 时走 RTSP |
| 检测按钮点了只有弹窗、按钮不变色 | — | 这是设计行为：串口测试结果用弹窗告知，按钮不保留颜色标记 |
| 关掉窗口程序还在跑 | 托盘图标 | 关闭按钮 = 隐藏到托盘；托盘右键"退出(Exit)"才真正退出 |
| 退出后仍有进程 | 任务管理器 | 正常退出后应剩 0 个；运行期 2 个同名进程是正常的（主进程 + 检测子进程） |
| 关程序时弹 `Failed to remove temporary directory` | — | 旧单文件版遗留问题，新文件夹版已消除；可清理历史 `%TEMP%\_MEI*` 残留 |
| 改了代码重新运行没变化 | 打包 | 若现场跑的是打包版，必须重新执行 `一键打包.bat` 后才生效 |

## 11. 已知限制

* 模型为车轮 / 轮轴检测模型，精度取决于现场光照、相机角度与安装高度，ROI 必须按现场标定。
* 拼接图在车辆变道或相机抖动时可能错位，属该类算法的固有特性。
* 主要验证素材为手持跟拍视频（960×544）；固定工业相机场景的调参待复测。
* 串口 / TCP / HTTP 转发需按现场设备联调（协议 0/1 需硬件串口）。
* 界面与自启、串口等能力以 Windows 平台为准，未在其他系统上验证。
